# 사용자 활동 DB

## 저장 구조

같은 [카카오봇DB 스프레드시트](https://docs.google.com/spreadsheets/d/1ECWcE98IMRm9PItPpK6rEC7dmmxbuT3Jtu3aFnaeccQ/edit)에 사용자 계정, 방별 상태, 반복되는 이력을 분리했다. 닉네임으로 계정을 연결하지 않는다.

| 탭 | 식별 기준 | 저장 내용 |
| --- | --- | --- |
| DB_UserId | user_id | 기존 사용자 정보, experience(K열), level(L열) |
| DB_RoomUsers | chat_id + user_id | 방별 닉네임, is_present, 마지막 관찰 시각, 상태 기준 로그, 경험치 지급 기준 |
| DB_RoomEvents | chat_id + log_id + user_id | join(입장), leave(퇴장), kick(강퇴), 발생 시각, 당시 닉네임 |
| DB_NicknameHistory | event_key | 방·사용자 ID, 변경 전후 닉네임, 관찰 시각, 관찰 출처 |

사용자 ID와 로그 ID, 누적 경험치는 문자열 + RAW로 저장해 큰 정수의 반올림을 피한다. 시각은 시간대가 포함된 ISO 8601 문자열이며 `Z`는 UTC다. 채팅 조회 결과의 시각은 실행 PC의 현지 시각으로 표시한다.

기존 A:J와 보관용 DB 탭은 유지했다. 기존 사용자 9명의 경험치는 0, 레벨은 1로 시작한다. 과거 기여도나 포인트에서 경험치를 추정하지 않는다. 기존 퇴장·강퇴 합계는 보존하지만, 합계만으로 과거 입퇴장 이력을 만들어 넣지 않는다.

## 경험치와 레벨

- 일반 텍스트 채팅·답글을 수신하면 1점을 지급한다.
- 동일 사용자에게 모든 방을 합쳐 최소 60초 간격으로 지급한다. 사용자가 승인한 기본 규칙이다.
- 슬래시로 시작하는 명령어, 시스템 메시지, 본인 봇 메시지, 1:1 인증 메시지에는 지급하지 않는다.
- 마지막 지급 시각과 방별 메시지 번호를 저장해 재시작 후에도 제한과 중복 방지를 유지한다.
- 레벨 1은 0점, 레벨 2는 누적 100점, 레벨 3은 300점, 레벨 4는 600점이다.
- 레벨 L의 시작 경험치는 `100 * (L - 1) * L / 2`다. 레벨은 경험치로 계산한다. L열만 수정하면 다음 저장에서 계산값으로 돌아간다.

## 참여 상태와 닉네임

선택한 방의 `chatMembers.isActive`를 약 5초마다 읽어 참여 여부를 보완한다. 새 입장·퇴장·강퇴와 일반 채팅도 상태에 반영한다. 오래된 로그가 최신 재입장 상태를 덮어쓰지 않도록 기준 로그 번호를 비교한다. 캐시에 행이 없다는 이유만으로 퇴장이라고 단정하지 않는다.

`is_present`는 TRUE(참여), FALSE(퇴장), 빈 값(미확인)이다. 봇이 꺼져 있거나 다른 방을 수신 중이면 마지막으로 확인한 상태가 남는다. 실시간 여부는 `last_seen_at` 등 관찰 시각과 함께 판단한다. 정확한 현재 상태는 카카오톡의 로컬 참여자 캐시 갱신 시점에도 영향을 받는다.

닉네임은 방마다 다를 수 있어 변경 이력도 방별로 나눈다. 최초 확인한 이름은 기준값으로 삼는다. 채팅·이벤트 또는 프로필 갱신에서 이름이 바뀌면 이전 이름과 새 이름을 기록한다. 프로필 이력의 `observed_at`은 실제 변경 순간이 아닌 봇이 확인한 시각이다. 봇이 보지 못한 중간 닉네임은 복원하지 않는다.

## 저장과 조회

- 입퇴장 이벤트와 채팅에서 확인한 닉네임 변경은 수신 묶음 직후 저장한다.
- 일반 경험치·참여자 스냅샷·프로필 관찰은 기존 약 60초 저장 주기에 모아서 반영하고, 정상 중지·종료할 때도 남은 변경을 저장한다.
- 사용자와 방 상태, 새 이력은 한 번의 Values.BatchUpdate 요청에 담는다. 이력은 이미 저장한 행을 매번 다시 쓰지 않고 신규 행만 지정된 위치에 저장한다. 응답 유실 후 재시도해도 같은 행에 기록한다.
- 로드한 이벤트 키로 동일 이벤트의 강퇴·퇴장 재집계를 차단한다. 저장 실패 시 대기 상태를 유지하며 미저장 상태에서는 정상 종료를 완료하지 않는다. 강제 종료 시 마지막 저장 이후의 변경은 잃을 수 있다.
- 봇 실행 중에는 시트 행을 수동 정렬·삭제하거나 여러 봇 인스턴스에서 같은 시트를 동시에 수정하지 않는다. 단일 작성자를 전제로 한다.
- `/조회`, `/조회 @사용자`에 레벨·누적 경험치·다음 레벨 기준·현재 방 상태·최근 입퇴장 5건·닉네임 변경 5건을 표시한다. 전체 이력은 해당 시트에서 확인한다.

외부 코드에서 읽을 수 있는 API:

```csharp
User user = Database.Instance.GetOrAddUser(userId);
long experience = user.Experience;
int level = user.Level;
RoomUser room = Database.Instance.FindRoomUser(chatId, userId);
bool? present = room == null ? null : room.IsPresent;
var events = Database.Instance.RoomEvents;
var names = Database.Instance.NicknameHistory;
```

스키마 생성·로드는 시작 시 수행한다. 헤더·ID·이력 형식이 잘못됐거나 활동 행에 대응하는 사용자 계정이 없으면 빈 목록으로 대체하지 않고 시작을 중단한다.

## 검증

`tests/Test-UserActivity.ps1`: 경험치 간격, 방 간 제한, 레벨 경계, 큰 정수 저장, 재시작 중복 방지, 과거 이벤트와 최신 상태의 순서, 닉네임 이력.

`tests/Test-UserIdentity.ps1`: 실제 봇의 메시지 처리부터 경험치·이력·조회·종료 저장 상태까지 연결 검증.

`tests/Test-ChatDatabaseReceiver.ps1`: 합성 DB의 참여자 상태 조회, 프로필 없는 작성자, 지연 시스템 이벤트 및 기존 복호화 회귀 검증.

실제 서비스 계정으로 4개 탭의 스키마를 읽는 점검을 수행했다. 실제 채팅 전송이나 사용자 입퇴장 조작은 하지 않았다.
