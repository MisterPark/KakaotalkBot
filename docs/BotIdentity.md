# 고정 봇 ID와 새 스프레드시트

## 연결

- 새 DB: https://docs.google.com/spreadsheets/d/12EdLFoc0uLGsRr5TX36CEqj2tO8PVrDzYICfEUHAmeI/edit
- 기존 DB의 셀과 공유 설정은 이관 과정에서 변경하거나 삭제하지 않습니다.
- 새 DB에는 기존 18개 탭과 키 확인용 `DB_Identity` 탭이 있습니다.
- 사용자 식별 컬럼은 `bot_user_id`입니다. JSON 이력 안의 `UserId`, `AuthorId`, `RevokedBy` 값과 사용자 ID가 포함된 복합 키도 `bot_...` 값으로 저장합니다.
- 메모 작성자, 칭호 부여·취소자, 퀘스트 보상 키도 변환합니다. 방 ID, 메시지 ID, 시간, 포인트는 사용자 ID로 변환하지 않습니다.

## PC 이동

1. 기존 PC의 봇을 종료하고 최신 저장소를 다른 PC에 옮깁니다.
2. `KakaotalkBot/BotIdentity.json`을 반드시 함께 가져옵니다. 사용자 요청에 따라 비공개 Git에서 보관할 수 있게 프로젝트에 포함했습니다.
3. 빌드하면 EXE 옆에 이 파일이 복사됩니다. 실행 파일만 옮길 때도 `BotIdentity.json`과 기존 Google 서비스 계정 `credentials.json`을 함께 옮깁니다.
4. 기존 시트 ID가 남은 `settings.json`은 실행 시 새 시트 ID로 전환됩니다. 다른 설정은 유지합니다.

동일 키는 PC, 닉네임, 채팅방에 관계없이 동일 사용자를 동일 봇 ID로 변환합니다. 신규 사용자도 자동으로 처리하므로 별도 매핑 목록을 합칠 필요가 없습니다. 두 PC에서 동시에 봇을 운영하면 기존 시트 저장 방식에 따른 덮어쓰기 충돌이 생길 수 있으므로 한 PC만 운영합니다.

## 키 보관

`BotIdentity.json`의 `Key`는 실제 카카오톡 ID를 복원할 수 있는 비밀키입니다. 운영진에게 공유할 대상은 새 스프레드시트이며, 이 키나 키가 포함된 저장소·실행 폴더는 공유하지 않습니다. 키를 삭제하거나 새로 생성하지 마세요. 잃어버리면 비공개 Git 또는 백업에서 같은 파일을 복원합니다.

PC에 종속된 암호화는 사용하지 않습니다. 별도의 256비트 암호화 키와 256비트 인증 키로 AES-CBC와 HMAC-SHA256을 사용하며, ID 동일성 유지를 위해 전용 인증 키에서 IV를 결정적으로 유도합니다. 인증 태그를 확인한 뒤에만 복호화합니다. 이는 사용자 ID 전용 형식이며 일반 메시지 암호화 용도로 사용하지 않습니다.

## 런타임과 저장 경계

카카오톡 DB, 명령 처리, 멘션 전송은 원래 `long user_id`를 사용합니다. `GoogleSheetHelper`가 시트를 읽을 때 복원하고 저장할 때 변환합니다. 시트에는 실제 ID와 변환 키를 기록하지 않습니다. 식별자 컬럼에 실제 ID가 들어 있거나 키가 다르면 읽기·저장을 실패시켜 기존 데이터를 보호합니다.

일반 텍스트의 알려진 사용자 ID도 봇 ID로 바꿉니다. 개인정보 전체를 익명화하는 기능은 아니므로 닉네임과 메모의 내용은 그대로 보입니다. `DB_Identity`에는 비밀키가 아닌 키 일치 확인값만 기록합니다.

## 검증과 이관 도구

- `tests/Test-BotIdentity.ps1`: 동일성, 64비트 정밀도, 다른 키·변조 거부, 방·로그 ID 보존, 각 이력의 왕복 변환을 검사합니다.
- `tools/IdentityMigration.cs`: 원본 읽기, 로컬 변환, 새 시트의 데이터·서식 복원에 사용한 도구입니다. 기존 원본 ID로의 복원 쓰기를 차단합니다.
- `tools/VerifyIdentityMigration.cs`: 새 시트를 읽어 전체 값·수식을 대조하고 봇의 실제 저장/읽기 경로를 검사합니다. `--write-check`는 기존 사용자 값을 변경 없이 새 DB에 다시 저장합니다.
- 이관용 원본 스냅샷은 Git에서 제외된 `artifacts/IdentityMigration` 아래에 보관합니다. 실제 ID가 포함된 파일이므로 운영진에게 공유하지 않습니다.

원본을 삭제하는 작업은 사용자가 직접 수행합니다. 기존 DB에 대한 접근 권한과 과거 다운로드 자료는 새 ID 도입만으로 없어지지 않습니다.

## 퀴즈 등록 권한

`BotIdentity.json`의 `SuperUserId`에는 슈퍼계정의 `bot_...` ID를 저장합니다. 닉네임으로 권한을 판정하지 않습니다. 설정을 바꾸면 봇을 재시작해야 하며, 다른 PC에도 같은 설정 파일을 복사합니다.

`/퀴즈등록 분류 | 난이도 | 문제 | 정답 | 힌트 | 해설`은 해당 방의 방장 또는 슈퍼계정만 가능합니다. 부방장은 등록할 수 없습니다. `/상식퀴즈`, `/퀴즈`, 분류별 퀴즈 호출, `/퀴즈목록` 조회와 정답 참여는 누구나 가능합니다. 등록은 기존 상식퀴즈 시트에 원문으로 추가하며, 진행 중인 퀴즈 종료 후 갱신된 문제 목록을 적용합니다. 방장 권한은 수신 세션에서 확인한 최신 참여자 정보로 검사하며, 오래되거나 확인 중인 정보는 허용하지 않습니다.

문제 삭제는 등록과 동일한 권한으로 `/퀴즈삭제 분류 | 문제 전체 문장`을 사용합니다. 정확히 일치하는 한 행만 삭제하며, 중복된 행이 있으면 삭제하지 않습니다. 진행 중인 문제를 삭제하면 해당 퀴즈를 종료하고, 다른 문제의 진행 상태는 유지합니다. 시트를 직접 정렬하거나 편집하는 동안에는 삭제 명령을 동시에 실행하지 마세요. 삭제 직전 원문 재확인은 하지만 Google Sheets는 행 삭제에 조건부 원자적 비교 기능을 제공하지 않습니다.
