# 오픈채팅 참여자 정리 — 이미지 인식 시험판

기존 봇과 분리된 .NET Framework 4.8 / Windows x64 프로그램입니다. DB, user_id, 로그인 정보 및 Google Sheets를 사용하지 않습니다.

## 실행

1. `Start.ps1`로 현재 소스를 빌드하고 실행하거나, `Build.ps1` 실행 후 `bin/Debug/OpenChatRoomCleaner.exe`를 엽니다. 실행 경로는 이 경로로 통일합니다. 예전에 전달한 다른 `bin` 하위 폴더는 이전 버전입니다.
2. 카카오톡의 대상 채팅방을 열고 프로그램에서 정확한 방 이름을 선택합니다.
3. 기본 선택된 **자동 시험 (최종 확인 직전 중지)** 모드로 시작합니다. 프로필과 내보내기 메뉴를 자동으로 열고, 최종 확인창이 인식되면 확인을 누르지 않고 종료합니다. **인식만 확인 (클릭 없음)** 모드는 직접 연 화면을 검사합니다.
4. 중지한 뒤 실제 실행이 필요하면 **실제 내보내기** 모드를 선택하고 시작합니다. 선택한 방과 전체 일반 참여자 내보내기를 확인하는 창이 표시됩니다.
5. **F8** 또는 중지 버튼으로 멈춥니다. 카카오톡을 다른 앱이 가리면 재확인하며 기다립니다.

배포 시 실행 파일 옆 `Assets` 폴더도 함께 복사해야 합니다. 개인정보가 있는 전체 캡처는 포함하지 않았습니다.

## 동작

- 참여자 목록 → 운영진 배지/본인 표시 제외 → 일반 참여자 프로필 → 내보내기&신고 → **내보내기** → 경고창. 자동 시험은 여기서 종료하고, 실제 실행 모드에서만 확인을 누릅니다.
- 프로필은 실측 Win32 클래스 `EVA_Window_Dblclk`, 300×600 기준 비율, `프로필 → 270 폭 참여자 목록 → 선택한 방` 소유 관계로 식별합니다. 핸들이 재사용되어도 표시 상태와 소유 관계를 검사합니다. 참여자는 닉네임 대신 프로필 이미지 중앙을 클릭합니다. 프로필 관리 버튼은 해당 창 하단에서 흰색 내보내기 화살표 모양을 찾아 클릭합니다. 버튼 수와 배경색에 따른 중앙/오른쪽 배치 차이를 처리하며, 아이콘을 찾지 못하면 대기합니다.
- 최종 확인 입력은 별도 액션 종류이며 자동 시험에서 입력 계층에서도 차단합니다.
- **내보내고 신고**는 사용하지 않습니다.
- 입력은 전용 STA 스레드에서 순차 실행합니다. 예상 이미지가 없으면 0.5초 간격으로 계속 확인합니다.
- 확인 클릭 이후 성공/실패를 DB로 검증하지 않습니다. 화면에는 **확인 클릭 시도 횟수**를 표시합니다.
- 일반 참여자가 보이지 않을 때 아래로 스크롤합니다. 유효한 목록이 3회 스크롤 후에도 동일하면 목록 끝으로 판정합니다. 맨 위도 같은 방식으로 확인하고 내려옵니다.
- 목록 행을 읽을 수 없는 상태는 완료가 아니라 대기입니다.

## 검증 범위와 제한

2026-10-13 사용자가 제공한 실제 화면 3장으로 5명/제외 3명/일반 2명 분류, 메뉴, 경고창 인식 및 상태 전이를 검증했습니다. 실제 사용자 내보내기와 실제 스크롤은 아직 검증하지 않았습니다.

현재 이미지와 행 간격은 제공된 화면의 배율/테마에 맞춘 시험판입니다. DPI/화면 배율/테마/카카오톡 버전이 바뀌면 다시 맞춰야 합니다. 인식 실패 시 자동으로 다른 좌표를 추측하지 않습니다.

스크롤 불변은 목록 끝의 **간접 판정**이므로 카카오톡이 멈추거나 스크롤이 무시되면 잘못 완료 판정할 여지가 있습니다. 큰 방에서 사용하기 전 실제 스크롤 시험이 필요합니다. 검색칸이 있는 84명 방의 캡처에서는 방장 제외, 완전히 보이는 5개 행, 일반 참여자 이미지 중앙 좌표를 추가 검증했습니다. 실제 스크롤 및 인원 변동 후 재탐색은 아직 검증 전입니다.

이미지 방식은 닉네임이나 ID를 기록하지 않습니다. 프로필을 수동으로 바꾸는 등 실행 중 카카오톡 조작은 피하고, 다른 자동 입력 봇은 중지한 상태에서 시험하세요.

## 캡처 회귀 시험

`Test.ps1`에 제공된 순서의 원본 캡처 3개 경로를 전달하면 실제 마우스 입력 없이 인식과 상태 전이를 시험합니다.

```powershell
.\Test.ps1 -ParticipantScreenshot '목록과프로필.png' -RemoveMenuScreenshot '내보내기메뉴.png' -ConfirmScreenshot '내보내기확인.png'
```

## 검색칸이 있는 목록

큰 방에서는 검색 입력칸을 먼저 찾고 그 아래에서 유저 행을 읽습니다. 아래쪽에 잘린 행은 선택하지 않습니다. 목록 인식 실패 이유를 표시하고, 실패한 목록을 방 헤더 재클릭으로 닫지 않습니다. `Test.ps1`의 `-LargeListScreenshot`으로 해당 캡처 시험을 추가할 수 있습니다.

## 실행 버전 확인

현재 창 제목과 로그에는 `[목록창-v5]`가 표시됩니다. 시작 로그에 실제 실행 파일 경로도 나옵니다. 이 표시가 없는 창의 로그는 현재 버전 로그가 아닙니다. 내부 `EVA_VH_ListControl_Dblclk`는 현재 버전의 목록 판독 대상이 아닙니다.

## 유지된 스크롤 위치 처리

목록을 처음 열거나 처리 후 다시 열었을 때, 행이 잘려 읽히지 않더라도 목록 영역이 확인되면 위로 스크롤합니다. 맨 위에서 화면이 안정되고 행을 읽을 수 있을 때만 참여자를 선택합니다. 행 판독 실패 상태로는 선택/완료 판정을 하지 않습니다.

## 운영진 배지 판독

운영진/본인 배지는 사각형 전체 대신 원 안쪽 픽셀을 비교하여 주변 사진과 선택 배경의 영향을 줄입니다. 배지 영역의 운영진 색상은 보이지만 모양이 확정되지 않는 행은 선택하지 않습니다. 불확실한 행만 남은 화면은 완료로 판정하지 않고 재인식합니다. 색상은 보조 판정이므로 프로필 사진 색에 의해 일반 참여자가 보수적으로 제외될 수 있습니다.

## 스크롤 후 운영진 행 정렬

운영진 목록을 13픽셀 이동한 합성 화면에서 이전 버전의 운영진 오선택을 재현했습니다. 현재는 배지 좌표로 화면에 온전히 들어오는 행 시작점을 다시 계산합니다. 13/24/37픽셀 이동과 실제 캡처 7장 회귀 시험을 통과했습니다.

클릭 직전 `Data/last-selection.png`에 행별 판정과 빨간 클릭점을 저장합니다. 초록은 운영진/본인 제외, 주황은 불확실해서 제외, 파랑은 일반 판정입니다. 같은 위치에 최신 한 장만 덮어씁니다. 목록의 닉네임과 프로필 사진을 포함하는 로컬 진단 이미지이며 서버 전송은 하지 않습니다.
